## Overall Impression

A confident, legible portfolio that earns its aesthetic. The system is internally consistent and the character is genuine. The single biggest opportunity is a hierarchy correction: the bio — the most important prose on the page — is styled in the lowest text tier, making the person's introduction feel quieter than their skill pills. That one change would make a noticeable difference to first-impression readability. Beyond that, a reduced-motion pass and a focus-visible style would close the two real accessibility gaps.

---

## What's Working

**1. The One Voice Rule holds.** Cold Signal (#38bdf8) appears only on skill labels, cert pills, borders, and hover states — never as fill, never decoratively. Because it's rare, it actually reads as a signal. This is hard to get right.

**2. The two-column layout makes efficient use of space.** Skills+certs on the left, projects on the right, with the vertical divider as a structural element rather than decoration. The panel slide for expanded projects keeps the user in context without a page navigation.

**3. No affordance theater.** Project rows are just rows — there's a dot, a name, a stack, an arrow. The cursor tells you it's clickable. No fake buttons, no card shadows trying to lift. The interaction is there when you need it, invisible otherwise.

## Priority Issues

### [P1] Bio text is in the lowest text tier
**What:** `color: var(--low)` (#888) on the bio paragraph — the same color used for skill pills, project names, and project descriptions. The `<strong>` tags inside the bio elevate to `var(--mid)` (#aaa), making the base bio text *dimmer than its own emphasis*.

**Why it matters:** The bio is the most important prose on the page. A recruiter or hiring manager reads it first. Presenting it at ghost-text weight means the sentence that introduces Eric reads quieter than "Cloud" in the skills section. This is a hierarchy inversion, not a contrast failure (the actual contrast passes WCAG AA at ~5.1:1), but it misrepresents information priority.

**Fix:** Change `.bio { color: var(--low) }` to `color: var(--mid)` (#aaa). The `strong` emphasis should then step up to `var(--text)` (#e0e0e0) to maintain the differential. The bio stays dark enough to feel right in the aesthetic; it just reads at the right weight.

**Suggested command:** `/impeccable polish`

---

### [P1] No `prefers-reduced-motion` fallback
**What:** Three animations have no reduced-motion alternative: the card entrance (`fadeUp` — translateY + opacity), view transitions (`viewIn` — opacity), and project panel slides (transform + opacity + visibility).

**Why it matters:** Users who have enabled "Reduce Motion" in their OS (vestibular disorders, motion sensitivity, epilepsy) get the full animation regardless. The fadeUp in particular — a vertical transform — is exactly the class of motion that triggers vestibular symptoms.

**Fix:** Add to the stylesheet:
```css
@media (prefers-reduced-motion: reduce) {
  .card { animation: none; }
  .view.visible { animation: none; }
  .proj-panel { transition: opacity .1s ease, visibility .1s; }
}
```

**Suggested command:** `/impeccable audit`

---

### [P2] No `:focus-visible` styles
**What:** Interactive elements (project rows with `tabindex="0"`, `.view-toggle` button, `.ext-link` anchors, `.proj-exp-close` button) rely entirely on browser-default focus outlines. On Chrome/dark backgrounds these are blue halos that clash with the aesthetic; on some configurations they may be invisible.

**Why it matters:** Keyboard-navigating the interface produces a jarring visual inconsistency — the only element that doesn't fit the design system is the focus ring that appears every time you tab. For users who rely on keyboard navigation, a visible focus indicator is not optional.

**Fix:** Add focus-visible rules that match the design: a 1–2px solid Cold Signal outline with a 2px offset works cleanly on dark backgrounds.
```css
:focus-visible { outline: 1.5px solid var(--accent); outline-offset: 2px; }
```

**Suggested command:** `/impeccable audit`

---

### [P2] Tagline icon inconsistency
**What:** The `_tIcons` map covers `Cloud`, `DevOps`, and `AppSec` — but the current tagline is `['Full Stack', 'DevOps', 'Cloud']`. "Full Stack" has no icon entry, so it renders as plain text while "DevOps" and "Cloud" render with an SVG prefix. The three items have different internal structure and therefore different visual rhythm.

**Why it matters:** The tagline is the second thing a viewer reads after the name. Inconsistent icon treatment looks like an oversight, not a choice.

**Fix:** Either add a "Full Stack" icon to `_tIcons`, or remove icons from the other two and keep the tagline text-only. Given the restrained aesthetic, text-only may actually be cleaner.

**Suggested command:** `/impeccable polish`

---

### [P2] 9px footer link
**What:** `.proj-footer a { font-size: 9px }` — the "more on github" link at the bottom of the project column is 9px in JetBrains Mono. This is below the `--sz-nav-btn: 10px` token defined in the design system (itself already very small), and well below any recommended minimum for interactive text.

**Why it matters:** 9px is difficult to read at normal viewing distance and very difficult on non-retina displays. As a link to more work, it's an important touchpoint given a noticeably lower visual weight than its content deserves.

**Fix:** Bump to `var(--sz-nav-btn)` (10px) or 11px. The "more on github" link benefits from being legible.

**Suggested command:** `/impeccable polish`

## Persona Red Flags

**Morgan (Hiring Manager / Recruiter — project-specific):** Arrives on the page looking to quickly assess: who is this, what do they do, do I want to talk to them? The name reads instantly (Bebas Neue 50px). The tagline is there but quiet (#888, 13px). The bio is also quiet (#888, 15px) — the introduction to the person is styled like supporting metadata. Morgan has to lean in to read the most important sentence on the page. The certs and skills are compact but scannable. Projects require a click to reveal descriptions — the initial list (name + 2 tags) is readable, and the expand is intuitive once discovered. The "more on github" link at 9px is easy to miss. Morgan will have read the page successfully, but the bio's visual weight doesn't match its importance.

**Sam (Accessibility-Dependent):** Tab order follows DOM structure: social links → project rows → close button when expanded. Project rows have `role="button"` and keyboard handlers — correct. No custom focus-visible styles: browser defaults will show something, but appearance is inconsistent with the design. No `prefers-reduced-motion` support: the card entrance and panel transitions play regardless of OS setting. No skip-to-content link: Sam must tab past all 3 social links before reaching the main content area. The expanded project close button is at `position: absolute; top: 12px; right: 12px` with `padding: 2px 4px` — approximately 18px touch/click target, below the 44px recommendation. Focus is correctly moved to the close button on expand (`setTimeout(() => focus(), 50)`) — that's a good detail.

**Casey (Distracted Mobile User):** Full-viewport card on mobile, clean. Skills and projects stack vertically — sensible. The project expand interaction works: tap row, see detail, tap ✕ to close. The ✕ close button's ~18px target is the most real mobile friction — a thumb tap on a small target in the top-right corner of the panel. Social links are at the top of the card (under the name) on mobile — the top of the screen, not the thumb zone. On a larger phone this requires a reach. The "more on github" footer link at 9px is effectively invisible on mobile.

## Minor Observations

- `snapCardHeight()` runs once at load; no `ResizeObserver` or window resize listener. Resizing the desktop window can leave the card at a stale fixed height until refresh.
- HTML `<title>` uses an em dash (`Eric Furspan — Full Stack Engineer`) while `CONFIG.meta.title` uses a regular hyphen (`Eric Furspan - Full Stack Engineer`). The OG title rendered in social shares would use the hyphen version.
- `overflow: hidden` on `.card-body` clips the expanded project panel. On very small desktop viewports with long project descriptions, content could be clipped.
- `white-space: nowrap` on `.proj-stack` — long technology names in future projects could overflow the column.
- The cert pill `title` attribute shows issuer and year on hover — a nice discovery detail that mobile users will never encounter (no hover). Consider showing this information permanently, or on tap.
